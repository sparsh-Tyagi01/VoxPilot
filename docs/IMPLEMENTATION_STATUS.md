# Architecture implementation status

Updated 15 November 2026. This tracks work against [the roadmap](ARCHITECTURE_AND_OPTIMIZATION_ROADMAP.md); the entire roadmap is not yet complete.

## Implemented

- **CPU-first Essential mode:** setup prepares speech recognition without waiting for WebGPU or a planner. Listening adds a bundled CPU speech detector. Unrecognized voice input returns quietly to listening; typed commands show a short text notice. The repeated spoken direct-command tutorial has been removed.
- **Neural speech detection:** a bundled Silero ONNX model runs in a separate single-thread WASM worker. A bounded queue, stale-frame epochs and a worker deadline prevent unbounded audio buffering. Detection requires speech probability and non-DC audio energy, followed by a minimum voiced duration and endpoint silence. A conservative energy fallback remains available if the detector cannot initialize. Silent/DC/tiny-noise audio is rejected again before Whisper decoding.
- **On-demand optional planners:** Assist/Advanced/Expert initialize their planner on the first complex request, not every microphone start. Profile aliases are normalized in one shared module.
- **Idle eviction:** optional GPU workers release resources after two minutes without an active request and reload on demand. Existing device-loss limits remain enforced.
- **Independent feedback:** page action completion no longer awaits a spoken summary. Short spoken confirmations are opt-in; explicit reading and clarification can still speak. Mic commands are suppressed during browser TTS to prevent feedback loops; Alt+V remains available. Only local system voices are used; otherwise feedback is text-only.
- **Audio framing:** duration-based 32 ms packets use transferable buffers. A stateful resampler preserves interpolation phase across packet boundaries at native sample rates.
- **Selective snapshots:** deterministic named-target commands skip headings and article-text extraction. Candidate queries are cached until DOM mutations invalidate them; geometry and metadata are read afresh. Snapshots carry a document identity and mutation revision. Plans retain their original document identity through confirmation, and page execution rejects navigation to another document. Click targets are checked again after scrolling yields; fields that become passwords or stop being editable are rejected.
- **Typing safety:** typing no longer sends Enter or submits a form. Submission must be requested as a separate action, such as clicking the actual submit control.
- **Message authority:** Chrome sender identity and role are checked separately from routing hints. Page confirmations must come from the bound top-frame tab. Page scripts cannot issue planner, settings, diagnostics, or passphrase operations through the content role.
- **Restart receipts:** the latest execution has bounded per-step dispatch/acknowledgment receipts in `storage.session`, containing action kinds and indices without field values or page text. An interrupted dispatch is marked uncertain after worker restart and is never automatically replayed. Receipts are included in diagnostics. Acknowledgment records a browser/content response, not proof of a business outcome.
- **Macro safety:** named clicks are rebound to unique labels in a fresh snapshot and use the normal confirmation, cancellation and receipt pipeline. Saved ephemeral handles are never used for macro fields. Missing/ambiguous labels and unsupported field targets fail explicitly; full semantic form macros remain unfinished.
- **Vault sessions:** field fills reuse one short-lived in-memory service-worker session rather than repeating PBKDF2 for each field. Explicit Settings locks and edits invalidate that session. Expiry is checked against wall-clock time even if browser timers are delayed, and a lock cancels pending asynchronous unlocks. Worker termination drops all session keys; no passphrase is persisted.
- **Diagnostics:** bounded in-memory samples for ASR, planning and action execution. Export from Settings → Privacy. Reports omit audio, transcripts, page text and field values. Successful samples and failures are counted separately. These are stage measurements, not annotated physical-speech-end SLO measurements.
- **Real-ASR benchmark tool:** Settings → Privacy accepts a short local audio recording, runs ten Whisper tiny q8/WASM inferences and exports initialization, first inference, warm timings and sample counts. It does not export the audio or transcript. Pause listening first. Initial model loading can download speech weights. Cache state is explicitly uncontrolled; this is not a full hardware qualification or annotated command corpus.
- **Package reduction:** ONNX JS and WASM are emitted from the same pinned dependency, with the old public copies omitted from the production package. Local uncompressed build size fell from about 60 MiB to about 30 MiB including the bundled speech detector. Build checks assert one runtime binary, glue and detector assets. WASM uses one thread until multi-thread/isolation behavior is qualified.
- **Canonical model metadata:** the unused parallel downloader with incomplete artifact lists and TODO hashes was replaced by a manifest view over the runtime profile configuration. Provider caches remain the storage owners. Unmeasured TPS and memory estimates were removed.
- **Privacy:** STT returns unknown confidence rather than a fabricated 100%. Opt-in history redacts transcripts, URLs, errors and content-bearing action arguments by default. This history store is JSON, not an encrypted vault; explicit raw-history preference must be treated accordingly.
- **Truthful settings:** removed fake zero-network audit output; unsupported cloud speech, idle mic timeout, barge-in and confidence-threshold controls are disabled rather than pretending to affect runtime behavior.

## Verification and use

Run `npm run check`: TypeScript, ESLint, unit/regression tests, production build and asset checks. Reload the built extension at `chrome://extensions` and refresh target pages. In Settings choose Essential for the CPU-only path. Existing users keep their stored profile until they change it.

Use a consented 0.3–30 second spoken-command recording under 10 MB for the benchmark. Compare the same recording across machines. Warm p95 from nine runs is a small-sample diagnostic, not production evidence. No benchmark corpus recordings were supplied or invented, and no real hardware latency target is claimed.

An isolated headless Chrome smoke test loaded the production VAD worker, Silero model and matching ONNX WASM/glue entirely from local build assets. It processed 100 silent 512-sample frames; maximum speech probability was approximately 0.043 against the 0.6 threshold. A separate run with 2.115 seconds of locally synthesized English speech reached approximately 0.9997 probability, with 60 positive speech frames. This verifies browser WASM execution on digital silence and a synthetic voice, not microphone accuracy or a representative speech/noise evaluation. The automated check passes 147 regression tests, including silence rejection, voiced endpoint delivery, stale frame rejection, classifier stalls, repeated unmatched voice input, document binding, restart receipts, macro confirmation and vault expiry.

## Remaining roadmap work

| Area | Status / prerequisite |
|---|---|
| Full trace correlation, cancellation spans, annotated end-to-end benchmarks and hardware scorecards | Partial: stage metrics and a real inference runner exist; physical speech-end annotations, representative audio/pages and device runs remain. |
| Streaming ASR selection | Not implemented. Neural VAD is integrated; compare recognition backends on a real benchmark corpus before migrating. Packet framing is not streaming recognition. |
| Revisioned incremental page index, candidate retrieval and frame/shadow-root support | Partial: revisioned candidate caching, selective text extraction and document binding exist. Fine-grained mutation patches, semantic retrieval and broader grounding remain. |
| Explicit submission action schema, postcondition verification, transactional undo and semantic macros | Partial: implicit submission is removed; named macro clicks are freshly grounded and risk checked. Field anchors, transactional undo and business postconditions remain. |
| Full artifact integrity/compatibility inventory and executable WebLLM bundling | Blocked for release: four libraries were retrieved for inspection, but the upstream binary repository's license endpoint was absent. Inspection files are staged outside the repository under `/tmp/voxpilot-model-libraries-review`. They are not bundled. Confirm redistribution rights or build licensed artifacts from source, then pin and package them. Optional WebLLM still uses its existing remote model-library path; store readiness is not claimed. |
| Vault session ownership and encrypted history option | Partial: short-lived worker-owned vault sessions, explicit invalidation and expiry are implemented. A dedicated offscreen secret owner and encrypted history option remain. Redaction must not be described as encryption. |
| Durable step receipts and restart reconciliation | Implemented for the latest execution within a browser session. Interrupted work is never replayed; cross-browser-restart persistence and business postconditions are not provided. |
| Browser-native ASR/AI adapters, extra languages, native companion or remote assist | Not implemented; remain optional later work, with explicit capability/privacy decisions. |
| Real Chrome microphone/inference/long-session validation and store review | Required before production release. Unit tests and a build are not substitutes. |

No implementation here establishes “best in class” performance. The next evidence-producing step is to run the benchmark and command fixtures on the target hardware, then select the speech backend and model policies from those results.
